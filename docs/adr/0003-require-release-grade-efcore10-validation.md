# Require release-grade validation for EF Core 10 support

EF Core 10 support is complete only when Debug and Release builds, NuGet packaging, unit tests, functional tests, migrations, scaffolding, and integration tests pass without unexpected failures across the existing Linux/Windows and MySQL/MariaDB CI matrix. Historical skips with specific documented causes may remain, but the upgrade must audit EF Core 10 skips, must not hide unported capabilities behind blanket ignored test bases, must cover the known optional-navigation `ExecuteDelete` regression, and must validate both the `10.0.0` compatibility floor and the latest stable EF Core 10 patch lane. Passing these gates authorizes an upstream contribution, not a release: local packages may be produced for verification, while release branding, tags, GitHub releases, and package publication remain under Pomelo maintainer control.
